¿Qué es y para qué sirve?

El conector SFTP/FTP permite que el agente de Ruvic intercambie archivos con un servidor remoto: listar carpetas, subir archivos generados, descargar archivos para procesarlos, moverlos entre carpetas, o eliminarlos. Sirve para integrarse con sistemas que reciben o entregan información por transferencia de archivos en vez de por una API — un patrón muy común en facturación electrónica, integraciones bancarias, EDI, y sistemas legados.

Una vez configurado, puedes pedirle al agente cosas como:

  • "¿Qué archivos hay en la carpeta de pedidos entrantes?"
  • "Sube este reporte a la carpeta de salida."
  • "Descarga el archivo de ayer y muéstrame su contenido."
  • "Mueve los archivos procesados a la carpeta de históricos."

Operaciones soportadas:

OperaciónQué hace
files.list_directoryLista el contenido de una carpeta remota
files.upload_fileSube un archivo nuevo
files.download_fileDescarga un archivo (retorna su contenido)
files.move_fileMueve o renombra un archivo
files.delete_fileElimina un archivo — de forma real y permanente
Este conector SÍ elimina archivos A diferencia de la mayoría de conectores de Ruvic, aquí delete_file ejecuta una eliminación real — no hay papelera de reciclaje ni deshacer. No existe una forma de bloquear esta operación desde el conector; si no quieres permitirla, no le des permiso de eliminación al usuario en el servidor.

Prerrequisitos

  • Un servidor SFTP (sobre SSH) o FTP/FTPS accesible por red desde donde corre Ruvic.
  • Un usuario dedicado a esta integración — no reutilices una cuenta personal.
  • Idealmente, que el servidor soporte restringir a ese usuario a una carpeta específica (chroot/jail) — así hay dos capas de protección: la del propio servidor y la de base_path del conector.
  • Para pruebas: puedes levantar un servidor SFTP local con Docker (ver sección de Verificación) en vez de usar un sistema productivo.

Configuración en el fabricante

Como este conector se conecta al servidor SFTP/FTP que ya tenga el cliente (no hay un "fabricante" único, como sí pasa con Salesforce u otros), los pasos varían según quién administre ese servidor. Guía general:

  1. Pide la creación de un usuario dedicado al administrador del servidor, con la contraseña o el par de claves SSH que se va a usar.
  2. Pide que se le restrinja a una carpeta específica (chroot) si el servidor lo soporta — evita que ese usuario pueda ver el resto del sistema de archivos, aunque haya algún error de configuración del lado de Ruvic.
  3. Si vas a usar SFTP con clave privada: genera un par de claves SSH dedicado (no reutilices tu clave personal), ej. con ssh-keygen -t ed25519 -f ruvic_sftp_key, y entrega la clave pública al administrador para que la autorice en el servidor. La clave privada es la que se pega en el formulario de Ruvic — nunca la pública.
  4. Anota la huella digital del servidor (host key) para SFTP, si quieres verificarla en Ruvic (recomendado). Puedes obtenerla conectándote una vez por SSH normal: 
    ssh -o FingerprintHash=sha256 usuario@servidor
    Va a mostrarte una línea como SHA256:AbCdEf1234... — esa es la huella a pegar en el campo "Huella digital del host".
  5. Confirma la carpeta exacta donde el agente va a trabajar (será tu base_path).
SFTP vs. FTP Si tienes la opción de elegir, usa SFTP (sobre SSH): es el más extendido hoy en día, cifra todo por defecto, y no requiere abrir rangos de puertos adicionales como sí necesita FTP en modo pasivo. Usa FTP solo si el sistema con el que te integras no ofrece SFTP.

Permisos requeridos

Permiso en el servidorPara qué lo usa el conector
Lectura sobre el directorioNecesario para list_directory y download_file
Escritura sobre el directorioNecesario para upload_file y move_file
Eliminación sobre el directorioNecesario solo si se va a usar delete_file — si prefieres no permitirlo, no otorgues este permiso

No pidas acceso de administrador del servidor ni acceso a otras carpetas fuera de la que el agente realmente necesita usar.

Configuración en Ruvic

Entra a Settings → Conectores, busca la tarjeta SFTP / FTP y pulsa Configurar. Elige el modo según lo que tengas:

ModoCuándo usarlo
SFTP con usuario y contraseñaEl caso más común para servidores SFTP
SFTP con clave privada SSHSi el administrador prefiere autenticación por clave en vez de contraseña
FTP / FTPSSolo si el sistema no ofrece SFTP

Completa el Host, las credenciales del modo elegido, y el Directorio raíz permitido (base_path) — deja este último bien acotado a la carpeta que el agente realmente necesita usar, no la raíz completa del servidor salvo que sea necesario.

Si tienes la huella digital del host (sección anterior), pégala en "Huella digital del host" para que cada conexión verifique la identidad del servidor.

Guarda y pulsa Probar conexión.

Verificación

  1. Test de conexión exitoso. El botón Probar conexión debe responder: "Conexión exitosa a [host] (sftp/ftp)".
  2. Prueba mínima con el agente. Pide algo de solo lectura primero:
    "¿Qué archivos hay en la carpeta configurada?"

Para probar sin depender de un servidor real, puedes levantar uno local con Docker:

docker run -d -p 2222:22 -v /tmp/sftp-data:/home/pruebas/upload \
  atmoz/sftp pruebas:contraseña123:1001

Y configurar el conector con Host localhost, Puerto 2222, usuario pruebas, contraseña contraseña123, y directorio raíz /upload.

Solución de problemas

Mensaje / síntomaCausa probable y solución
"Autenticación SFTP/FTP fallida"Usuario, contraseña o clave incorrectos. Verifica con el administrador del servidor.
"No se pudo conectar..." (timeout/red)El servidor no es alcanzable desde donde corre Ruvic — puede requerir VPN, whitelist de IP, o el puerto está bloqueado por un firewall.
"La huella digital del host no coincide"O bien la huella configurada está mal copiada, o el servidor realmente cambió de identidad (posible problema de seguridad real) — no ignores este error sin confirmar con el administrador.
"Ruta no permitida... fuera del directorio raíz"El agente intentó acceder a una ruta fuera de base_path — es la protección funcionando. Si es un caso legítimo, amplía el base_path configurado.
"Sin permisos para..."El usuario del servidor no tiene el permiso necesario sobre esa carpeta/archivo. Revisa la sección de Permisos requeridos.
list_directory retorna tamaños/fechas vacíos (FTP)El servidor FTP no soporta el comando MLSD; es una limitación conocida del protocolo FTP clásico, no un error.

Preguntas frecuentes y notas de seguridad

¿El agente puede eliminar cualquier archivo del servidor?

Solo dentro del base_path configurado, y solo si el usuario del servidor tiene permiso de eliminación en esa carpeta. Fuera de eso, no.

¿Qué es la "huella digital del host" y por qué debería configurarla?

Es un identificador único del servidor SSH. Configurarla evita que alguien intercepte la conexión haciéndose pasar por tu servidor real (ataque man-in-the-middle). Sin ella, el conector acepta la identidad del servidor la primera vez que se conecta (igual que hace tu terminal cuando usas SSH por primera vez a un host nuevo) — funciona, pero es menos seguro.

¿Dónde quedan guardadas las credenciales?

Como secreto en el almacén de credenciales de la plataforma. La interfaz nunca vuelve a mostrarlas.

Rotación de credenciales

Pide al administrador del servidor que rote la contraseña o regenere el par de claves SSH periódicamente, y actualiza el valor correspondiente en el formulario del conector.

Buenas prácticas Usa siempre un usuario dedicado y acotado a una carpeta específica (chroot si es posible); prefiere SFTP sobre FTP; activa FTPS si no tienes alternativa a FTP; configura la huella digital del host en SFTP; y no otorgues permiso de eliminación en el servidor salvo que el caso de uso realmente lo requiera.
